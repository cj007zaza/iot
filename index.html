ความหมายของ IoT, องค์ประกอบของระบบ (End Nodes, Connectivity, Cloud Server), ความรู้ด้าน Hardware/Software, การประยุกต์ใช้งานในชีวิตจริง (Smart Home, Smart City, Connected Car, Smart Farming) และการจำแนกประเภทบอร์ดประมวลผล

💡 ประเด็นสำคัญและสาระสำคัญประจำบท (Key Highlights)
  • IoT คือ อุปกรณ์อิเล็กทรอนิกส์ที่สามารถรับ-ส่งข้อมูลถึงกันได้ผ่านอินเทอร์เน็ตโดยอัตโนมัติ
  • องค์ประกอบหลัก 3 ส่วน: 1. End Nodes (เซนเซอร์/บอร์ด), 2. Connectivity (ระบบเครือข่าย), 3. Central Servers / Cloud (ประมวลผลและจัดเก็บข้อมูล)
  • การประยุกต์ใช้: Smart Home, Smart Wearable, Smart City, Connected Car, Smart Retail, Smart Farming
  • บอร์ดประมวลผลแบ่งเป็น 2 กลุ่ม: Microcontroller (ขนาดเล็ก งานเฉพาะ) และคอมพิวเตอร์ขนาดเล็ก (Single Board Computer เช่น Raspberry Pi ติดตั้ง OS ได้)

KidBright & Simulator

การใช้งานโปรแกรม KidBright Simulator ในการจำลองการทำงานของบอร์ด KidBright, เครื่องมือบล็อกคำสั่ง (Basic, Math, Logic, Loop, Wait, Music, Sensor, Clock, I/O) และการเชื่อมต่อเซนเซอร์จำลองภายนอกกว่า 18 ชนิด

💡 ประเด็นสำคัญและสาระสำคัญประจำบท (Key Highlights)
  • KidBright เป็นบอร์ดสมองกลฝังตัวเพื่อการเรียนรู้ ใช้ ESP32 มีหน้าจอ LED 16x8, สวิตช์ 2 ปุ่ม, เซนเซอร์แสง, เซนเซอร์อุณหภูมิ, RTC และลำโพง Buzzer ในตัว
  • แถบคำสั่งบล็อกหลัก: Basic, Math, Logic, Loop, Wait, Music, Sensor, Clock, I/O
  • เซนเซอร์และโมดูลภายนอกที่รองรับ: Soil Moisture, Force, PIR Motion, IR Avoidance, Tracking, Gas LPG, Rain, Sound, Ball Switch, Button, Shock, Tilt, Flame, Metal Touch, Reed Switch, มอเตอร์ขับเคลื่อน
  • โจทย์โครงงาน: ออกแบบโครงงานแก้ปัญหาชุมชนโดยใช้เซนเซอร์ใน KidBright Simulator

อิเล็กทรอนิกส์พื้นฐาน

ความรู้พื้นฐานด้านไฟฟ้าและอิเล็กทรอนิกส์: กฎของโอห์ม, ตัวต้านทานและการอ่านรหัสแถบสี, ตัวต้านทานปรับค่าได้, ตัวเก็บประจุ, หลอด LED และการคำนวณตัวต้านทานจำกัดกระแส, ไดโอด, สวิตช์ AC/DC, ไมโครสวิตช์, วงจรรวม (IC), เบรดบอร์ด และการต่อเซลล์ไฟฟ้า

💡 ประเด็นสำคัญและสาระสำคัญประจำบท (Key Highlights)
  • กฎของโอห์ม (Ohm's Law): V = I x R (แรงดัน = กระแส x ความต้านทาน)
  • การอ่านรหัสแถบสีตัวต้านทาน: ดำ(0), น้ำตาล(1), แดง(2), ส้ม(3), เหลือง(4), เขียว(5), น้ำเงิน(6), ม่วง(7), เทา(8), ขาว(9), ทอง(±5%), เงิน(±10%)
  • หลอด LED (Light Emitting Diode): ทำงานด้วยไฟ DC 3V กระแสประมาณ 20mA ต้องต่อตัวต้านทานจำกัดกระแสเสมอ คำนวณด้วยสูตร R = (Vsource - Vled) / Iled
  • ตัวเก็บประจุ (Capacitor): ทำหน้าที่เก็บและคายประจุ (ฟารัด F) แบ่งเป็น อิเล็กโทรไลติก (มีขั้ว), เซรามิก (ไม่มีขั้ว ทน 50-100V ค่า < 1uF), ไมลาร์ (ทนแรงดันสูง 350V ค่า > 1uF)
  • เบรดบอร์ด (Breadboard): แถวแนวนอนด้านบน-ล่างเป็นรางไฟเลี้ยง (Power Rails ต่อทะลุกันยาว), แถวแนวตั้งตรงกลางเชื่อมต่อกันเป็นแถวละ 5 ช่อง
  • การต่อเซลล์ไฟฟ้า: แบบอนุกรม (Series: แรงดันรวมเพิ่มขึ้น Vt = V1 + V2), แบบขนาน (Parallel: แรงดันเท่าเดิม แต่จ่ายกระแสได้นานขึ้น)

📌 ไดโอดเปล่งแสง (LED)

LED คือไดโอดเปล่งแสง ย่อมาจากคําว่า(Light-Emitting Diode) ซึ่งสามารถ

เปล่งแสงออกมาได้แสงที่เปล่งออกมาประกอบด้วยคลื่นความถี่เดียวและเฟสต่อ

เนื่องกัน ซึ่งต่างกับแสงธรรมดาที่ตาคนมองเห็น โดยหลอด LED สามารถเปล่ง

แสงได้เมื่อจ่ายกระแสไฟฟ้าเข้าเพียงเล็กน้อยเท่านั้น

และประสิทธิภาพในการให้

แสงสว่างก็ยังดีกว่าหลอดไฟขนาดเล็กทั่วๆ ไป.

📌 ตัวเก็บประจุ

ตัวเก็บประจุ หรือ คาปาซิเตอร์ (Capacitor หรือ Condenser) หรือเรียกย่อ ๆ ว่าตัวซี (C) เป็นอุปกรณ์

อิเล็กทรอนิกส์ที่ทำหน้าที่เก็บประจุ (Charge) และคายประจุ (Discharge) บางครั้งเรียกตัวเก็บประจุนี้ว่า

คอนเดนเซอร์ (Condenser) ซึ่งเป็นอุปกรณ์พื้นฐานสำคัญในงานด้านอิเล็กทรอนิกส์ และพบได้ในวงจร

อิเล็กทรอนิกส์ เช่น วงจรกรองกระแส วงจรขยายสัญญาณ ตัวเก็บประจุแบ่งออกเป็น 3 ชนิด คือ แบบค่า

คงที่ แบบเปลี่ยนแปรค่าได้ และแบบปรับค่าได้ หน่วยของตัวเก็บประจุคือ ฟารัด F (Farad)

💡 ประเด็นสำคัญและสาระสำคัญประจำบท (Key Highlights)

Digital & Analog I/O

โครงสร้างภาษา C++ สำหรับ Arduino, ตัวแปร, ตัวดำเนินการเปรียบเทียบและลอจิก, เงื่อนไข if-else, คำสั่ง Digital Output (pinMode, digitalWrite, delay), Analog Output ด้วย PWM (analogWrite), Digital Input (digitalRead) พร้อมวงจร Pull-up และ Pull-down, Internal Pull-up และการอ่านค่า Analog Input (analogRead)

💡 ประเด็นสำคัญและสาระสำคัญประจำบท (Key Highlights)
  • โครงสร้างคำสั่ง Digital: pinMode(pin, mode), digitalWrite(pin, value), digitalRead(pin)
  • PWM (Pulse Width Modulation): การจำลองสัญญาณแอนะล็อกเอาต์พุตสำหรับหรี่ไฟ LED หรือคุมความเร็วรอบ analogWrite(pin, 0-1023)
  • ปัญหาขาลอย (Floating Pin) และสวิตช์: ต้องใช้วงจร Pull-up (ปกติ HIGH กดแล้ว LOW) หรือ Pull-down (ปกติ LOW กดแล้ว HIGH)
  • โหมด INPUT_PULLUP: ใช้งานตัวต้านทาน Pull-up ภายในตัวชิป โดยไม่ต้องต่อตัวต้านทานภายนอกเพิ่ม
  • Analog to Digital (ADC): แปลงสัญญาณแอนะล็อกเป็นดิจิทัล 10-bit (ค่า 0 ถึง 1023) ด้วยคำสั่ง analogRead(pin)

📌 การควบคุมขา OUTPUT

การใช้งาน ขา OUTPUT ของ Arduino แบบ Digital โดยสั่งให้

Arduino เปิด/ปิด ไฟ LED ขั้นแรก ต้องเซตขา Arduino ให้เปน

โหมด OUTPUT ก่อนแล้วใช้คําสั่ง digitalWrite(); ในการควบคุม

สัญญาณ แบบ Digital มีเพียงแค 2 ค่า คือ เปิด หรือ ปิด ทุกขาของ

Arduino สามารถสั่งงานแบบ Digital ได้ทุกขา

Arduino สามารถทำงานแบบ digital ได้ 2 แบบคือ

1 แบบ INPUT สำหรับอานค่าวา ขานั้นมีไฟ หรือ ไม่มีไฟ
2 แบบ OUTPUT สำหรับส่งค่า เปิดไฟ/ปิดไฟ ออกไป
💡 คำอธิบายเชิงลึกและสาระสำคัญของภาพสไลด์:
การควบคุม Digital Output และไฟกระพริบ LED (ขา D2 หรือ GPIO22): • คำสั่ง pinMode(D2, OUTPUT); กำหนดขาให้พร้อมส่งแรงดันไฟ • คำสั่ง digitalWrite(D2, HIGH); จ่ายไฟออก 3.3V/5V (ไฟติด) • คำสั่ง digitalWrite(D2, LOW); สั่งไฟออก 0V (ไฟดับ)

void setup() {
  pinMode(22, OUTPUT); // กำหนดขา GPIO 22 เป็น OUTPUT
}

void loop() {
  digitalWrite(22, HIGH); // สั่งเปิดไฟ LED
  delay(500);             // หน่วงเวลา 0.5 วินาที
  digitalWrite(22, LOW);  // สั่งปิดไฟ LED
  delay(500);             // หน่วงเวลา 0.5 วินาที
}

#define LED 22
#define SW 23

void setup() {
  pinMode(SW, INPUT_PULLUP); // ใช้งาน Internal Pull-up (ไม่กด=1, กด=0)
  pinMode(LED, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  int sw = digitalRead(SW);
  Serial.println(sw);
  if (sw == 0) {            // เมื่อกดสวิตช์ (สภาวะ Active Low)
    digitalWrite(LED, HIGH); // สั่งเปิดไฟ LED
  } else {
    digitalWrite(LED, LOW);  // ปิดไฟ LED
  }
}

📌 DHT11 Digital Temperature and Humidity Sensor DHT11

DHT11 เป็นเซนเซอร์วัด อุณหภูมิ (°C) และ ความชื้น (%)

ใช้ สัญญาณดิจิทัล ส่งข้อมูลออกมาทางขา Data เพียงขาเดียว

💡 คำอธิบายเชิงลึกและสาระสำคัญของภาพสไลด์:
เซนเซอร์วัดอุณหภูมิและความชื้น DHT11 (Digital Sensor): • วัดอุณหภูมิย่าน 0 - 50 °C (ความแม่นยำ ±2°C) และความชื้น 20 - 90% RH (ความแม่นยำ ±5%) • ส่งข้อมูลแบบ Digital ผ่านสายสัญญาณ Data เพียงเส้นเดียว (Single-Bus) • การต่อวงจร: VCC ต่อ 3.3V, GND ต่อ GND, Data ต่อ GPIO ของ ESP32 (เช่น GPIO4 หรือ GPIO22) • ต้องติดตั้งไลบรารี: 'DHT sensor library by Adafruit' และ 'Adafruit Unified Sensor'
💻 ตัวอย่างโค้ดโปรแกรม 
#include <DHT.h>

#define DHTPIN 4     // ขา DATA ของ DHT11 ต่อเข้ากับ GPIO4
#define DHTTYPE DHT11

DHT dht(DHTPIN, DHTTYPE);

void setup() {
  Serial.begin(9600);
  dht.begin();
}

void loop() {
  float h = dht.readHumidity();    // อ่านค่าความชื้น (%)
  float t = dht.readTemperature(); // อ่านค่าอุณหภูมิ (°C)

  if (isnan(h) || isnan(t)) {
    Serial.println("Failed to read from DHT sensor!");
    return;
  }

  Serial.print("Humidity: ");
  Serial.print(h);
  Serial.print("%  Temperature: ");
  Serial.print(t);
  Serial.println("°C");
  delay(2000);
}

MQTT & HiveMQ Cloud

รู้จักกับโปรโตคอล MQTT (Message Queuing Telemetry Transport), สถาปัตยกรรม Publish / Subscribe, หน้าที่ของ Broker, Publisher, Subscriber, การออกแบบ Topic, ระดับคุณภาพบริการ (QoS 0, 1, 2), โครงสร้างข้อมูล JSON, การตั้งค่า HiveMQ Cloud, การใช้โปรแกรม MQTT Explorer และการทดลองส่งค่าเซนเซอร์ DHT11 ขึ้น Cloud แสดงผลบน Web

💡 ประเด็นสำคัญและสาระสำคัญประจำบท (Key Highlights)
  • MQTT เป็นโปรโตคอลการสื่อสารที่เบา (Header แค่ 2 ไบต์) ประหยัดแบนด์วิดท์และพลังงาน เหมาะกับ IoT
  • รูปแบบ Publish / Subscribe มี 3 ส่วนสำคัญ: Broker (ตัวกลางจัดการข้อความ), Publisher (ผู้ส่งข้อมูล), Subscriber (ผู้รอรับข้อมูล)
  • การส่งข้อมูลอิงตามชื่อหัวข้อ (Topic): เช่น classroom/group01/temperature โดยผู้ส่งและผู้รับไม่จำเป็นต้องรู้จักกันโดยตรง
  • ระดับ QoS (Quality of Service): QoS 0 (At most once ส่งครั้งเดียว), QoS 1 (At least once ได้รับอย่างน้อยหนึ่งครั้ง), QoS 2 (Exactly once ได้รับถูกต้องแน่นอนครั้งเดียว)
  • การใช้งาน HiveMQ Cloud: สมัครบัญชี สร้าง Cluster, กำหนด Access Management และ Topic Filter Permissions
  • โปรแกรม MQTT Explorer: ซอฟต์แวร์บน PC สำหรับมอนิเตอร์และทดสอบส่ง-รับข้อความ MQTT แบบ Real-time
  • Lab 13: ต่อ DHT11 กับ ESP32 ส่งค่าอุณหภูมิ-ความชื้นเข้า HiveMQ ผ่านไลบรารี PubSubClient และนำข้อมูลไปแสดงผลบน Dashboard เว็บไซต์

📌 MQTT

จุดเด่นของ MQTT

  • เบา: ใช้ header ข้อความเล็กมาก (แค่ 2 bytes ก็เพียงพอ)

  • ประหยัดพลังงาน: เหมาะกับอุปกรณ์ IoT ที่ใช้แบตเตอรี่

  • ทำงานบน TCP/IP: ใช้งานง่ายกับเครือข่ายทั่วไป

  • มี QoS (Quality of Service) 3 ระดับ

  • 0: ส่งครั้งเดียว อาจหายได้

  • 1: ส่งอย่างน้อย 1 ครั้ง (อาจซ้ำ)

  • 2: ส่งครั้งเดียวแน่นอน (ไม่ซ้ำ ไม่หาย)

💡 คำอธิบายเชิงลึกและสาระสำคัญของภาพสไลด์:
จุดเด่นและระดับคุณภาพบริการ (QoS - Quality of Service): • ส่วนหัวแพ็กเกจ (Header) มีขนาดเล็กมากเพียง 2 ไบต์ ช่วยประหยัดแบตเตอรี่และแพ็กเกจอินเทอร์เน็ต • QoS 0 (At most once): ส่งครั้งเดียว ไม่มีการตอบรับ ข้อความอาจสูญหายได้ • QoS 1 (At least once): รับรองว่าส่งถึงแน่นอนอย่างน้อย 1 ครั้ง (อาจมีข้อความซ้ำได้) • QoS 2 (Exactly once): ระดับสูงสุด รับรองว่าส่งถึงแน่นอนเพียงครั้งเดียว ไม่ซ้ำและไม่สูญหาย

#include <WiFi.h>
#include <PubSubClient.h>
#include <DHT.h>

#define DHTPIN 22
#define DHTTYPE DHT11
DHT dht(DHTPIN, DHTTYPE);

const char* ssid = "YOUR_WIFI_SSID";
const char* password = "YOUR_WIFI_PASSWORD";
const char* mqtt_server = "YOUR_HIVEMQ_CLUSTER_URL";
const int mqtt_port = 8883; // SSL/TLS port
const char* mqtt_user = "YOUR_MQTT_USERNAME";
const char* mqtt_pass = "YOUR_MQTT_PASSWORD";

WiFiClientSecure espClient;
PubSubClient client(espClient);

void setup() {
  Serial.begin(115200);
  dht.begin();
  // เชื่อมต่อ Wi-Fi และตั้งค่า MQTT Server
  WiFi.begin(ssid, password);
  client.setServer(mqtt_server, mqtt_port);
}

void loop() {
  if (!client.connected()) {
    // ฟังก์ชันเชื่อมต่อ MQTT Reconnect
  }
  client.loop();

  float t = dht.readTemperature();
  float h = dht.readHumidity();

  // ส่งข้อมูล (Publish) ขึ้นสู่ HiveMQ Cloud
  char payload[50];
  snprintf(payload, sizeof(payload), "{\"temp\":%.1f,\"hum\":%.1f}", t, h);
  client.publish("classroom/group01/data", payload);

  delay(5000); // ส่งข้อมูลทุก 5 วินาที
}

📌 ขาใช้งาน NodeMCU ESP32 & Arduino Cheat Sheet

บอร์ด NodeMCU-32S มีขา GPIO ทั้งหมดรองรับฟังก์ชันหลากหลาย โดยมีข้อควรระวังในการเลือกใช้งานดังนี้:

  • ขาใช้งานทั่วไป (General GPIO): GPIO 16, 17, 18, 19, 21, 22, 23 (แนะนำใช้งานได้อย่างปลอดภัย ไม่รบกวนระบบบูต)
  • ADC1 (Analog Input): GPIO 32, 33, 34, 35, 36 (VP), 39 (VN) — สามารถอ่านค่า analog ได้แม้เปิดใช้ Wi-Fi
  • ADC2: ใช้งานร่วมกับวงจร Wi-Fi หากเปิด Wi-Fi จะไม่สามารถอ่านค่า ADC2 ได้
  • Input Only Pins: GPIO 34, 35, 36, 39 — เป็นขาอินพุตอย่างเดียว ไม่มีตัวต้านทาน Pull-up/Pull-down ภายใน และสั่ง OUTPUT ไม่ได้
  • Strapping Pins (ห้ามดึงไฟขัดขวางตอนบูต): GPIO 0, 2, 5, 12, 15
คำสั่งสำคัญใน Arduino C++:
pinMode(pin, OUTPUT); / pinMode(pin, INPUT_PULLUP);
digitalWrite(pin, HIGH / LOW);
int val = digitalRead(pin);
int raw = analogRead(A0); (ค่า 0 ถึง 1023 ในบอร์ด 10-bit หรือ 0-4095 ใน ESP32 12-bit)
📡 สรุปสถาปัตยกรรม MQTT & HiveMQ Cloud

รูปแบบการสื่อสาร Publish / Subscribe

MQTT เป็นโพรโทคอลที่ทำงานบน TCP/IP โดยใช้นายหน้า (Broker) เป็นศูนย์กลางกระจายข้อความ:

1. Publisher
อุปกรณ์ตรวจวัดหรือเซนเซอร์ ส่งข้อความ (Message Payload) ไปยังหัวข้อ (Topic) ที่ระบุ
2. Broker (HiveMQ)
เซิร์ฟเวอร์ตัวกลางตรวจสอบ Topic และส่งข้อความต่อไปยัง Subscriber ที่รอรับ
3. Subscriber
แอปพลิเคชันหรือแดชบอร์ดที่กด Subscribe หัวข้อที่ตนเองต้องการมอนิเตอร์

ระดับคุณภาพบริการ QoS (Quality of Service)

  • QoS 0 (At most once): ส่งเพียงครั้งเดียว ไม่มีการยืนยัน ข้อความอาจหล่นหายได้เมื่อสัญญาณเน็ตหลุด
  • QoS 1 (At least once): ส่งซ้ำจนกว่าจะได้รับข้อความยืนยัน (ACK) รับรองว่าถึงชัวร์ แต่อาจมีข้อความซ้ำซ้อน
  • QoS 2 (Exactly once): ระบบยืนยัน 4 ขั้นตอน รับรองว่าถึงแน่นอนเพียงครั้งเดียว ไม่ซ้ำและไม่หาย
